# Database Documentation

## 1. Overview

This document describes the database structure, relationships, migrations, integrity constraints, and verification tests implemented for the Humanitarian Crisis Management Platform.

## 2. Database Tables

The application database contains the following entities:

- Users
- CrisisEvents
- AssistanceRequests
- AIRecommendations
- Shelters
- Resources
- Volunteers
- Donations
- Organisations
- Notifications

## 3. Database Relationships

The following foreign key relationships are configured:

| Related Entity | Referenced Entity | Delete Behavior |
|---|---|---|
| AIRecommendation | AssistanceRequest | Cascade |
| Shelter | CrisisEvent | SetNull |
| Resource | CrisisEvent | SetNull |
| Volunteer | CrisisEvent | SetNull |
| Donation | CrisisEvent | SetNull |
| Resource | Shelter | SetNull |
| Volunteer | Shelter | SetNull |

Foreign key indexes are generated by Entity Framework Core.

## 4. Database Integrity Constraints

The database enforces the following CHECK constraints:

### Resources
- Quantity must be greater than or equal to zero.

### Shelters
- Capacity must be greater than or equal to zero.
- CurrentOccupancy must be greater than or equal to zero.
- CurrentOccupancy cannot exceed Capacity.

These constraints prevent invalid values from being stored in the database.

## 5. Database Migrations

The database schema is managed using Entity Framework Core migrations.

The migration history includes:

- InitialCreate
- AddDonations
- AddRemainingModules
- AddCrisisConnections
- AddDatabaseRelationships
- AddDatabaseIntegrityConstraints

## 6. Database Verification Tests

### Relationship Tests

Run the following command:

    sqlite3 humanitarian_test.db < DatabaseTests/verify_relationships.sql

The tests verify:

- Database integrity
- Foreign key validation
- Cascade delete behavior
- Crisis event SetNull behavior
- Shelter SetNull behavior
- Test data cleanup

### Integrity Constraint Tests

Run:

    python3 DatabaseTests/verify_integrity_constraints.py

The tests verify that:

- Negative resource quantities are rejected.
- Negative shelter capacity is rejected.
- Negative shelter occupancy is rejected.
- Occupancy exceeding capacity is rejected.
- Zero resource quantity is accepted.
- Zero shelter capacity and occupancy are accepted.

## 7. Test Database

The verification scripts use a separate SQLite database named humanitarian_test.db.

This database is used for testing and is not part of the committed application source files.

## 8. Test Database Setup

Create or update the separate test database by running:

    ConnectionStrings__DefaultConnection="Data Source=humanitarian_test.db" dotnet ef database update

Run the verification scripts after the migrations have been applied.
